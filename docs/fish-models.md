# 用户鱼模型接入

## 资源

- 用户提供的 Tripo GLB 原件：`assets/source/uploaded-fish.glb`。
- 网页实际加载：`public/models/fish/uploaded-fish.glb`。
- 与模型一致的渲染缩略图：`public/models/fish/uploaded-fish.webp`。

原件 3,102,696 字节、108,920 个三角面、64,006 个顶点，包含一张 1024 × 1024 JPEG 基础色贴图；不含骨骼和动画。网页轻量版 1,064,256 字节、19,604 个三角面，保持原有纹理坐标和内嵌贴图，不依赖在线解码器或外部贴图 URL。

原件保留在源码目录中，不会被 Vite 复制到网页构建产物。重新生成轻量版：

```sh
node scripts/optimize-fish.mjs assets/source/uploaded-fish.glb public/models/fish/uploaded-fish.glb
```

简化目标为原面数的 18%，最大误差参数为模型半径的 0.001。每份新模型仍需目视检查轮廓、鱼鳍、贴图与动画。

## 在应用中使用

素材库的“你的 3D 鱼模型”入口会显示真实渲染图。选择该模型对应的鱼种后，那个鱼种的所有鱼儿将使用此模型。如果缸内没有该鱼种且未达到 30 条上限，会加入一条便于观察。也可从设置中管理，支持恢复原有造型和撤销重做。

模型未带鱼种身份信息，因此不自动将其识别成某个物种。默认保持未分配状态，由用户选择对应鱼种；总鱼种数保持 10 种。映射保存为 `TankState.modelSpecies`，旧版存档缺省为 `null`，可以继续读取。

## 运行与动画

`src/fish-model.ts` 使用 GLTFLoader 异步加载模型，烘焙原始节点变换、居中并统一长度，将原件的负 Z 朝向旋转为鱼运动系统的正 X 朝向。`src/fish-assets.ts` 保存资源路径、朝向校正和长度比例。

这是一份静态模型。新增的程序化顶点变形会让身体与尾部沿横向小幅波动，并修正表面法线；每条鱼使用不同的相位，避免完全同步。现有游动、转向、喂食行为由鱼演员外层对象继续驱动。这不是新增了骨骼或专业游动动作，胸鳍等局部动作仍有提升空间。

同一鱼缸中的多条鱼共享加载结果、几何与纹理，每条鱼独立拥有材质和动画参数。移出鱼只释放该鱼的材质；关闭鱼缸时统一释放共享资源。加载完成后会检查鱼是否仍然存在、映射是否仍然有效，避免已删除的鱼被异步回调重新加入。资源加载失败时保留原造型并给出提示。

`src/fish-model.test.ts` 覆盖坐标校正、纹理坐标保留、共享资源生命周期、延迟加载取消和发布资源面数／体积。`src/model.test.ts` 覆盖旧存档兼容与映射校验。
