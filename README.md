# 一方水景 · A Little Aquarium

[在线试玩](https://kuma0595.github.io/FishTank/) · [GitHub 源码](https://github.com/Kuma0595/FishTank)

单鱼缸 Web 原型。用 Vue 3 + TypeScript + Three.js 实现，主要体验是淡水鱼观赏与自由造景。

## 本地运行

```sh
npm install
npm run dev
```

默认地址由 Vite 输出。验证与构建：

```sh
npm test
npm run build
npm run preview
```

## 当前功能

- 单个 60 × 30 × 30 cm 的展示鱼缸与温暖桌面环境。
- 10 种鱼：金鱼、白云金丝、青鳉、孔雀鱼、红绿灯、斑马鱼、玛丽鱼、月光鱼、斗鱼、熊猫鼠鱼。
- 鱼种检索、分类、加入与移出，最多 30 条；鱼模型以体形、配色、条纹和尾鳍区分，白云金丝直接使用用户提供的 GLB 模型。
- 游动、转向、基础造景避让、尾鳍摆动、底栖活动与投喂聚集。
- 孔雀鱼专用曲面模型：收窄尾柄、带褶皱的半透明扇尾、鳍条与不规则斑纹、虹彩鳞片、眼睛及鳃盖；三种稳定配色，身体波动与胸鳍独立动画。
- 用户 GLB 鱼模型接入：真实贴图、轻量化、程序化身体摆动、白云金丝固定绑定、共享资源和旧存档兼容。详见 [模型接入说明](./docs/fish-models.md)。
- 7 种造景素材：爪哇蕨、苦草、红丁香、前景草、青灰岩、溪流卵石、枝状沉木。
- 点选放置、直接拖动、旋转、缩放、位置调整、复制、移除与 35 步撤销／重做。
- 三种底砂配色、水草灯开关、水面微动、水草摆动、气泡与装饰性焦散纹理。
- 自由、正面、俯视视角；隐藏界面观赏；下载当前三维画面的 PNG。
- IndexedDB 自动保存；校验后的 JSON 导入与导出；恢复初始鱼缸可撤销。
- 桌面与手机布局，弹窗焦点约束与基础键盘操作。

## 操作

拖动画面旋转相机，滚轮缩放。在“造景”中选择素材后，点击缸底放置；选择已有造景后可直接拖动，或使用参数面板调整。`Esc` 取消放置／退出观赏／关闭弹窗；`Delete` 移除当前造景；`Cmd/Ctrl + Z` 撤销，`Cmd/Ctrl + Shift + Z` 重做。

鱼缸保存在当前站点、当前浏览器的本地数据库，跨域或换设备需要导出／导入。首次进入使用初始场景。导入前会验证版本、素材 ID、对象数量、唯一标识和变换范围，避免无效文件破坏场景。

## 范围与后续

当前为自由创作原型，不模拟水质、疾病、繁殖、混养相容性、经营收益、离线生长或真实水动力。鱼种分类用于素材导航，青鳉和斑马等广温鱼只在一个分类中显示，不代表严格的生物学边界。静态陈设中的过滤器暂不产生生态效果。

造景为缸底摆放，限制物体中心的位置；未实现精确模型碰撞、壁面安装、物体堆叠、底床雕刻或用户模型上传。默认鱼模型、植物与房间是代码生成的风格化造型；白云金丝使用用户提供的 GLB 模型，无需手动选择对应鱼种。没有实机性能承诺；手机布局验证是在浏览器尺寸模拟中进行的。

后续可沿当前 catalog／model／scene 的分层增加精细素材、更多淡水鱼，以及多缸和海缸。首版没有引入后端、账号或网络存档。

## 结构

- `src/guppy.ts`：孔雀鱼曲面、程序化鳞片／鳍膜材质、个体配色及游动。
- `src/catalog.ts`：鱼种与造景的独立目录。
- `src/model.ts`：存档格式、校验、初始场景与 IndexedDB。
- `src/scene.ts`：Three.js 场景、编辑拾取、鱼运动与动画资源生命周期。
- `src/App.vue`：素材库、操作流程、历史记录和存档界面。
- `src/model.test.ts`：往返存档、快照隔离、无效输入与空缸恢复测试。

物种身份参考 FishBase：[金鱼](https://www.fishbase.org/summary/Carassius_auratus.html)、[白云金丝](https://www.fishbase.se/summary/Tanichthys-albonubes)、[红绿灯](https://www.fishbase.se/summary/10691)、[月光鱼](https://www.fishbase.se/summary/Xiphophorus-maculatus.html)。这些参考用于命名，不构成本应用对真实饲养的指导。界面字体使用 Google Fonts，可在网络不可用时回退至系统中文字体。

## GitHub Pages 发布

源码位于 `main`，构建产物位于 `gh-pages`。Pages 发布源为 `gh-pages` 分支的根目录，访问地址为 https://kuma0595.github.io/FishTank/ 。Vite 使用相对资源路径，同时适配项目子路径与本地预览。

本项目的默认交付流程是：完成修改与必要验证后，由 Codex 提交并推送源码到 GitHub，再自动执行 Pages 发布并检查结果，无需再次提醒或确认。约定见 [AGENTS.md](./AGENTS.md)。这里的自动发布由 Codex 在交付过程中执行。

手动操作时，先提交并推送源码，再运行：

```sh
npm run deploy
```

此命令先进行类型检查和生产构建，成功后在临时目录更新 `gh-pages`，不切换当前工作分支、不强制推送。它需要仓库写权限；已登录的 GitHub CLI 会被用于 Git 认证，否则沿用 Git 自身的认证配置。Pages 随发布分支的更新自动部署，执行结果可在仓库 Actions 或 Settings → Pages 查看。

仅推送 `main` 不会更新网页；每次发布都需要执行上述命令。使用 GitHub Pages 时不需要 `.openai/hosting.json`，该文件仅保留原有 Sites 部署配置。不同站点使用各自的本地存档，需要通过 JSON 导出／导入迁移。
